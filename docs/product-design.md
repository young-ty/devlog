# DevLog 产品设计文档

> 状态：V1–V3 均已交付 · 初版 2026-09-05 · 2026-10-11 对齐实现现状

## 1. 背景与问题

个人开发者做完一个项目后，复盘往往无从下笔：

- 过程素材散落：Git 记录了"做了什么"，但"为什么这么做"和踩坑经过大多只存在记忆里；
- 决策理由丢失：几个月后连自己都说不清当初为什么选 A 不选 B；
- 面对空白文档没有抓手：回忆全靠脑补，费时且不完整。

## 2. 产品定位

**本地优先、以 Git 仓库为唯一事实来源的个人开发复盘工具：项目结束后一键生成"有据可查、人机共创"的结构化复盘文档。**

差异化价值：

- **零侵入**：不需要在开发过程中安装或记录任何东西，任意已经结束的 Git 项目立刻可用；
- **有据可查**：每条 AI 结论都可回溯到具体 commit，防幻觉；
- **人机共创**：AI 还原"发生了什么"，人负责回答"为什么、学到了什么"；
- **本地数据**：产物是 Markdown + JSON，可版本化、可迁移。

## 3. 设计原则

1. V1 只依赖 Git 历史，不引入任何"使用前先养习惯"的捕获机制；
2. AI 负责整理事实，不做超出素材的断言；无法从 Git 得出的内容转成引导提问；
3. 每条论断带来源引用；AI 推断显式标注"待确认"，用户确认后生效；
4. 诚实处理信息不足：`wip`、merge、静默期等低信息量时段明确标注，而不是编造过程；
5. 界面作为"共创台"而非"展示台"：重点是逐条确认与编辑。

## 4. 核心用户流程

```
选择 Git 仓库与时间范围
  → 解析 commit / diff（噪音分类、主题聚类）
  → AI 分块摘要 → 结构化复盘草稿
  → 人工逐条确认 / 编辑 / 回答引导问题
  → 导出 Markdown 到 docs/retrospectives/
```

## 5. 主要功能模块

### M1 项目接入与事件建模

- 输入 Git 仓库路径 + 时间范围（日期区间 / 起止 commit / tag）；
- 解析 commit 元数据与文件变更，识别 merge、revert、wip、chore 等噪音；
- 把散落 commit 聚类为开发主题，识别里程碑与异常静默期；
- 事件落进本机 SQLite 缓存（`~/.devlog/devlog.db`），不以 commit hash 作业务主键：
  历史改写后按项目重扫即可对齐，缓存本身随时可重建。

### M2 AI 复盘生成流水线

- 大仓库增量 / 分块摘要，控制 token 与成本；
- 按复盘文档 schema 结构化输出，带字段校验、重试与失败回退；
- 复盘板块：项目概述 / 开发时间线 / 技术决策记录 / 问题与解决 / 踩坑总结 / 可复用资产 / 遗留与下一步；
- 每个论断内联 commit 来源；AI 推断标注"待确认"；
- 基于素材缺口生成引导问题（如静默期发生了什么、决策理由是什么）。

### M3 复盘文档管理与编辑

- 草稿分板块确认、修改，确认状态可视化（待确认 → 已确认）；
- 阅读视图可直接通读成稿，并支持「定稿 / 撤回定稿」；
- 导出 Markdown；支持同一仓库的多期复盘；
- 产物落在项目仓库内，天然可版本化。

### M4 离线评测集（工程质量保障）

- 人工标注的 golden set（当前 9 条用例，见 `devlog/eval/cases.py`）；
- 离线跑规则版候选，按覆盖度、来源精确率 / 召回率与类型匹配打分，在线可再加
  LLM 打分；平均分低于阈值即判不通过；
- prompt 与流水线改动跑回归，防止质量劣化。

## 6. 前端界面（现状：六个页面）

- **项目列表 / 项目工作台**：注册仓库、扫描、Git 派生统计；
- **开发时间线**：提交、Bug、笔记、静默期挂在同一条可拖动的曲线上，
  卡片可展开看来源，也能就地写批注；
- **AI 复盘**：生成草稿 → 逐条确认 / 回答引导问题 → 阅读视图定稿归档 / 导出；
- **每日复盘**：当天提交与捕获的 Bug 汇总成一屏，一键起草；
- **Bug 现场**：捕获报错 / 环境 / Git 状态，事后补根因与解法；
- 深色 / 浅色双主题，颜色全走 CSS 变量。

## 7. 数据与产物

- 本地状态库：`~/.devlog/devlog.db`（SQLite：项目、commit 缓存、草稿与论断、
  翻译缓存、每日笔记、Bug 记录、批注与引导回答），随时可从 Git 重建；
- 复盘文档：`<仓库>/docs/retrospectives/*.md`，唯一落进用户仓库的产物；
- 每条论断的数据结构：`{ text, sources: [commit...], status: fact | ai_pending | confirmed | edited }`；
- 界面只消费核心库 API，CLI 与 Web 共用同一套领域逻辑。

## 8. 路线图

- **V1（已交付）**：M1-M4 + CLI + 本地 Web 界面，端到端可用；
- **V2（已交付）**：Bug 一键捕获（报错 + 环境 + Git 状态）、开发中批注、每日复盘、
  事件融入时间线与复盘素材；
- **V3（已交付）**：复盘成稿（只收人工确认过的内容）与定稿归档。

踩坑知识库与语义检索已移出本项目范围：在本地工具里最多做到 `LIKE`
全文匹配，讲不出检索质量；DevLog 只负责把复盘做扎实。

## 9. 非目标与边界

- 不做团队协作、云端托管、需求 / 方案文档管理；
- 不替代项目管理工具；
- AI 只生成草稿，不替代人的反思与确认。

## 10. V1 成功标准

- 任意一个已有真实历史（数百 commits）的 Git 仓库，能在几分钟内产出可编辑复盘草稿；
- 草稿中每条事实论断都能回溯到 commit；
- 评测集可运行、可量化，流水线改动可通过回归；
- 用本工具给自己至少一个真实项目完成复盘（dogfooding）。
